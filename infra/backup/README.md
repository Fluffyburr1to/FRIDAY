# Backup Configuration

Litestream configuration, restore scripts, and recovery-card generation.

See [infra/README.md](../README.md) for the three-tier design and
[Chapter 34](../../docs/01-bible/34-disaster-recovery.md) for the full strategy.

## The two things that must never be skipped

**1. Encryption before egress.** Backblaze stores a blob it cannot read. The key lives in your
Keychain **and** on the printed recovery card. If the key exists in only one place, it does not
exist.

**2. Nightly restore verification.** Restore, check SQLite integrity, **verify the audit hash chain
end to end**, confirm the newest event is recent, destroy the copy. Any failure notifies at
`urgent`.

> A backup you have never restored is not a backup. It is a hypothesis.

## The recovery card

Generated by `tools/scripts/recovery-card.ts`. Printed, stored physically, verified annually.

Contains: the backup encryption key, B2 bucket and read credentials, passkey recovery codes, a short
restore procedure, and the runbook URL.

**Without it, encrypted backups are indistinguishable from random noise.** Setup is not complete
until the card exists.
